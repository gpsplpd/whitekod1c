# JSON-схема ответа LLM — версия 1.0

Артефакт этапа 3. Один источник правды для промпта (`02-system-prompt-v1.md`), валидатора (`УмныйИмпортВалидацияJSON`) и тест-набора (`06-test-set.csv`).

**Версия схемы: `1.0`.** Версия пишется в журнал `ЖурналВызововLLM` вместе с каждым ответом — без этого невозможно объяснить, почему вчера парсилось лучше.

---

## 1. Структура ответа

Модель возвращает **один JSON-объект** на одну строку исходных данных (при пакетировании — массив таких объектов, см. §6).

```json
{
  "schema_version": "1.0",
  "row_id": 1,
  "артикул": "45120",
  "наименование": "Насос центробежный АЦ-100",
  "единица_измерения": "шт",
  "цена": 12500.00,
  "кратность_упаковки": null,
  "примечание": null,
  "confidence": 0.95
}
```

### 1.1. Поля

| Поле | Тип | Обязательность | Правила |
|---|---|---|---|
| `schema_version` | Строка | Обязательно | Ровно `"1.0"`. Если модель вернула другую версию — ответ считается невалидным по схеме |
| `row_id` | Число (целое) | Обязательно | Эхо `row_id` из запроса. Нужен для сопоставления ответа с исходной строкой при пакетировании |
| `артикул` | Строка или `null` | Обязательно поле (значение может быть `null`) | Только артикул «как есть» из строки, без префиксов `арт.`/`art.`/`№`. Ведущие нули сохраняются (`"0012345"`). Максимум 50 символов |
| `наименование` | Строка | Обязательно, непустое | Товарное наименование **без** артикула, цены, единицы измерения и служебных пометок. Максимум 200 символов |
| `единица_измерения` | Строка или `null` | Обязательно поле | Каноническое значение из справочника синонимов (см. `03-normalization-rules.md`). Если единица в строке отсутствует — `null`, **не** подставлять «шт» |
| `цена` | Число или `null` | Обязательно поле | Число ≥ 0, разделитель — точка, без пробелов-разделителей, без валюты и без пометок НДС. `12500.00`, а не `"12 500,00 руб."` |
| `кратность_упаковки` | Число (целое) или `null` | Обязательно поле | Целое ≥ 1. `null`, если в строке кратность не указана — **не** подставлять 1 |
| `примечание` | Строка или `null` | Обязательно поле | Всё, что не попало в остальные поля: срок поставки, аналог, «с НДС», состояние, страна. Максимум 200 символов |
| `confidence` | Число 0..1 | Обязательно | Самооценка модели по всей строке. Используется только для сортировки предпросмотра «сначала сомнительные», **не** для автоматического отбрасывания строк |

### 1.2. Расширение сверх кейса

`schema_version`, `row_id`, `confidence` — поля, которых нет в требованиях кейса. Назначение: версионирование (иначе невозможно интерпретировать исторические логи), пакетирование и приоритизация ручной проверки. На защите позиционировать как инженерное решение, а не как требование заказчика.

## 2. Семантическая валидация в 1С

Три уровня защиты (промпт → транспортный ремонт JSON → семантическая валидация). Здесь — третий уровень, он реализуется в `УмныйИмпортВалидацияJSON`.

### 2.1. Проверки по полям

| Поле | Проверка | Нарушение → |
|---|---|---|
| весь объект | Разбирается `ЧтениеJSON`; корень — объект, не массив (кроме режима пакетирования) | `Ошибка` |
| `schema_version` | Равна ожидаемой версии | `Ошибка` |
| `row_id` | Присутствует и совпадает с запрошенным | `Ошибка` |
| `наименование` | Непустое после нормализации; длина ≤ 200; не совпадает с `артикул` после нормализации | Пустое/длинное → `Ошибка`; совпадает с артикулом → `ТребуетВнимания` |
| `цена` | Число; 0 ≤ цена ≤ 1 000 000 000 | Не число → `Ошибка`; вне диапазона → `ТребуетВнимания`; `null` → `ТребуетВнимания` |
| `артикул` | Строка ≤ 50; после нормализации непустой | `null`/пусто → `ТребуетВнимания` (поиск по наименованию); > 50 символов → `Ошибка` |
| `единица_измерения` | Входит в канонический список `03-normalization-rules.md` | Не входит → `ТребуетВнимания`; `null` → `ТребуетВнимания` |
| `кратность_упаковки` | Целое 1..100 000 или `null` | Дробное/отрицательное → `ТребуетВнимания`; > 100 000 → `ТребуетВнимания` |
| `примечание` | Строка ≤ 200 | Длиннее → обрезать, статус `ТребуетВнимания` |
| `confidence` | Число 0..1 | Отсутствует → `0.5`, статус не меняется |

### 2.2. Статусы строки

| Статус | Условие | Что видит оператор | Отметка «к загрузке» |
|---|---|---|---|
| `ОК` | Все проверки пройдены | Обычная строка | Стоит |
| `ТребуетВнимания` | Есть хотя бы одно замечание «мягкого» класса (см. §2.1) | Подсветка + список замечаний в колонке «Замечания» | Стоит — решает оператор |
| `Ошибка` | Невалидный JSON, таймаут, пустой ответ, нарушение схемы, отсутствует `наименование` | Подсветка красным, текст ошибки | Снята автоматически |
| `Пропущена` | Строка отбракована **до** вызова LLM (шапка, итог, пустая, < 2 потенциальных полей) | Серая, причина в колонке «Причина пропуска» | Снята, в LLM не отправлялась |
| `Уже загружено` | `ХешСтроки` + `Поставщик` найдены в `ЗагруженныеСтрокиИмпорта` | Жёлтая, ссылка на ранее созданный элемент | Снята, оператор может вернуть вручную |

Важно: `ТребуетВнимания` **никогда** не снимается с загрузки автоматически — иначе получаются скрытые потери данных. Автоснятие только для `Ошибка`, `Пропущена`, `Уже загружено`.

### 2.3. Разделение «до LLM» и «после LLM»

- **До вызова** (этап 4, правила отбраковки): если по предварительному разбору строка распознана как заголовочная/итоговая (все ячейки текстовые, есть «итого», «прайс», «артикул» в шапке) или содержит менее 2 потенциальных полей (одна ячейка без разделителей) — статус `Пропущена`, вызов не выполняется.
- **После вызова** (этап 5): если модель вернула менее 2 валидных полей — статус `ТребуетВнимания`, строка остаётся в предпросмотре и ждёт оператора.

## 3. Обработка невалидного JSON (транспортный уровень)

Порядок действий, реализуется в `УмныйИмпортИнтеграцияLLM` до семантической валидации:

1. Если провайдер поддерживает `response_format` (`json_object` / `json_schema`) — включаем, ответ всё равно проверяем.
2. Иначе — «ремонт»: срезать обёртки ```` ```json ````/```` ``` ````, найти первый `{` и последнюю `}`, отбросить преамбулу и постскриптум, проверить баланс скобок вне строковых литералов.
3. Если после ремонта `ЧтениеJSON` падает — **один** повторный запрос с сообщением: «Предыдущий ответ не является валидным JSON. Верни только JSON-объект по схеме, без пояснений.»
4. Второй невалидный ответ — статус `Ошибка`, текст ошибки в журнал. Повторных попыток больше не делаем (защита от роста стоимости).

---

## 4. Что модели запрещено

- Возвращать текст вне JSON, использовать markdown-обёртки (кроме случая, когда провайдер сам их добавляет — их снимает транспортный уровень).
- Придумывать артикул, цену или единицу измерения, которых нет в исходной строке.
- Подставлять значения по умолчанию (`шт`, `1`, `0`) вместо `null`.
- Объединять несколько исходных строк в один ответ.
- Возвращать `null` в `наименование`.
- Добавлять поля сверх схемы (лишние поля отбрасываются валидатором, но в журнал пишется признак «лишние поля»).

## 6. Режим пакетирования (Could, не включён по умолчанию)

При включённом флаге `ПакетироватьСтроки` в запрос уходит нумерованный массив строк, ответ — массив объектов той же схемы:

```json
[
  {"schema_version": "1.0", "row_id": 1, "...": "..."},
  {"schema_version": "1.0", "row_id": 2, "...": "..."}
]
```

Правила: число объектов равно числу строк в запросе; `row_id` уникальны и совпадают с запросом; при несовпадении количества — все строки пакета получают `Ошибка` и уходят на повтор по одной. Пакетирование включается только после замера на `06-test-set.csv` и сравнения с построчным режимом (падает ли точность).
