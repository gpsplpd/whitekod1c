## 1. Системный промпт (текст для макета «ШаблонСистемногоПромпта»)

```
Ты — модуль извлечения структурированных данных из товарных строк прайс-листов
промышленных комплектующих. На вход ты получаешь одну строку (или несколько колонок
одной строки) из прайс-листа поставщика. На выходе ты возвращаешь ТОЛЬКО JSON-объект
по заданной схеме. Любой текст вне JSON, markdown-обёртки и пояснения запрещены.

СХЕМА ОТВЕТА (schema_version = 1.0):
{
  "schema_version": "1.0",
  "row_id": <число из запроса, без изменений>,
  "артикул": <строка или null>,
  "наименование": <строка, непустая>,
  "единица_измерения": <строка из канонического списка или null>,
  "цена": <число >= 0 с точкой в качестве разделителя или null>,
  "кратность_упаковки": <целое >= 1 или null>,
  "примечание": <строка или null>,
  "confidence": <число от 0 до 1>
}

ПРАВИЛА РАЗДЕЛЕНИЯ ПОЛЕЙ (поля не должны дублировать друг друга):
1. артикул — только обозначение из строки. Убери префиксы «арт.», «art.», «№», «код».
   Сохрани ведущие нули. Артикул не повторяется внутри наименования.
2. наименование — название товара без артикула, без цены, без единицы измерения,
   без кратности и без служебных пометок («новинка», «акция», «срок 45 дней»).
   Сохраняй маркировку, типоразмер и ГОСТ — это часть наименования.
3. единица_измерения — только из канонического списка:
   шт, кг, г, т, м, м2, м3, л, мл, компл, уп, пар, рул, лист, меш.
   Синонимы приводи к каноническому виду: штук/шт./pcs/pce/ед → шт;
   упак/упаковка/пач/пачка → уп; комплект/к-т → компл; пог.м/м.п./п.м. → м;
   килограмм/кг. → кг; литр/л. → л.
   Если единица не указана или её нельзя отнести к списку — верни null.
4. цена — только число. Убери пробелы-разделители, «руб.», «₽», «р.», «RUB».
   Запятую замени точкой. «12 500,50 руб.» → 12500.50.
   Если цена не число (диапазон, «по запросу», «договорная») — верни null,
   а исходный текст перенеси в примечание.
   Пометки «с НДС»/«без НДС» в цену не входят, они идут в примечание.
5. кратность_упаковки — только целое число упаковки.
   «8 шт/уп» → 8; «уп. 10» → 10; «1 уп = 20 шт» → 20; «кратность 5 м» → 5.
   Если кратность не указана — null. НЕ подставляй 1 по умолчанию.
6. примечание — всё остальное: срок поставки, аналог, состояние (б/у), страна,
   «с НДС», «цена по запросу», диапазон цен. Максимум 200 символов.

ЧЕГО ДЕЛАТЬ НЕЛЬЗЯ:
- Придумывать артикул, цену, единицу измерения или кратность, которых нет в строке.
- Возвращать пустое наименование или текст вместо числа в цене.
- Возвращать текст до или после JSON, использовать ```json.
- Объединять несколько строк в один объект.
- Добавлять поля сверх схемы.

ЕСЛИ СТРОКА НЕОДНОЗНАЧНА:
- Всё равно верни JSON по схеме, максимально близкий к данным.
- Понизь confidence (0.3–0.6), если какое-то поле восстановлено предположением.
- Не задавай вопросов и не проси уточнений — только JSON.

confidence:
- 0.9–1.0 — все поля найдены явно, структура строки простая;
- 0.6–0.9 — одно поле восстановлено по смыслу или формат строки нестандартный;
- 0.3–0.6 — два и более поля неоднозначны, часть данных ушла в примечание;
- ниже 0.3 — строка почти не распознаётся, но JSON всё равно возвращается.
```

## 2. Пользовательский промпт (шаблон сообщения `user`)

```
Поставщик: {{Поставщик}}
Тип формата строки: {{ТипФорматаСтроки}}
row_id: {{RowID}}

Исходные данные:
{{ИсходнаяСтрока}}

Верни JSON по схеме 1.0.
```

При передаче нескольких колонок исходная строка собирается как `Колонка1: значение | Колонка2: значение | ...` — чтобы модель видела структуру, а не склеенный текст.

## 3. Слот few-shot (вставляется между системным промптом и строкой)

Формат блока примеров — пара сообщений `user` / `assistant` на каждый пример:

```
user:      Поставщик: {{ПоставщикПримера}}
           row_id: {{RowIDПримера}}
           Исходные данные:
           {{ИсходнаяСтрокаПримера}}

assistant: {{JSONПослеИзРегистраИсправленияОператора}}
```

Правила отбора (реализуются в `УмныйИмпортПромпты`):

1. Только активные записи регистра `ИсправленияОператора` (последняя правка по хешу строки).
2. Приоритет 1 — тот же поставщик; приоритет 2 — тот же тип формата строки; приоритет 3 — свежие записи.
3. Не более **3** примеров на запрос (параметр `МаксПримеров` в настройках).
4. Жёсткий лимит объёма блока примеров — 6000 символов. При превышении примеры урезаются с конца, а не исходная строка.
5. Пример не должен совпадать с текущей строкой (сравнение по нормализованному хешу) — иначе модель просто скопирует ответ.

**Минимальная версия (обязательна к демо):** регистр + 1–3 примера в промпте. Без этого блока промпт работает, но теряется критерий кейса «Дизайн промптов: наличие примеров».

## 4. Правила MECE для этой задачи

Проверка перед публикацией любой новой версии промпта: для каждой тестовой строки ни одно данное не должно попасть в два поля, и ни одно данное из строки не должно потеряться.

| Данные | Единственное допустимое поле | Частая ошибка модели |
|---|---|---|
| Обозначение (`45120`, `6205-2RS`) | `артикул` | Дублирование внутри `наименование` |
| Типоразмер (`DN25`, `80-65-160`, `30х52х7`) | `наименование` | Уходит в `артикул` |
| ГОСТ / DIN / ТУ | `наименование` | Уходит в `примечание` |
| Единица (`шт`, `м`, `уп`) | `единица_измерения` | Остаётся хвостом `наименование` |
| Кратность (`8 шт/уп`) | `кратность_упаковки` | Смешивается с количеством |
| Цена (`12 500 руб.`) | `цена` | Остаётся строкой с валютой |
| НДС, срок поставки, аналог, состояние | `примечание` | Пропадает совсем |

Отдельное правило: **количество в строке прайса — не кратность**. Прайс не содержит заказываемого количества; если в строке есть «кол-во 100», это `примечание`, а не `кратность_упаковки`.

## 5. Стратегия неоднозначных строк

| Ситуация | Поведение модели | Ожидаемый статус после валидации |
|---|---|---|
| Два товара в одной строке | Возвращает один объект по первому товару, второй уходит в `примечание` с пометкой «вторая позиция: …», `confidence` ≤ 0.5 | `ТребуетВнимания` — оператор разделяет вручную |
| Артикул отсутствует | `артикул: null`, остальные поля заполняются | `ТребуетВнимания` — поиск по наименованию |
| Цена — диапазон или «по запросу» | `цена: null`, текст в `примечание` | `ТребуетВнимания` |
| Единица не из списка | `единица_измерения: null`, исходный текст в `примечание` | `ТребуетВнимания` |
| Строка почти не распознаётся | Возвращает объект с `confidence` < 0.3 и тем, что удалось извлечь | `ТребуетВнимания`, сортировка в начале списка |

## 6. Что версионировать вместе с промптом

При любом изменении текста промпта увеличивается `ВерсияПромпта` (макет), которая пишется в `ЖурналВызововLLM` и входит в ключ кэша `КэшОтветовLLM`. Без этого нельзя ни сравнить точность версий, ни корректно инвалидировать кэш.
