# Инструкция оператора «Умного импорта»

Документ для менеджера по закупкам, который каждый день получает прайс-листы от поставщиков.
Технических знаний не требуется. Время на один файл — 1–3 минуты плюс правка «сомнительных» строк.

## 1. Что делает модуль

Берёт файл поставщика (XLSX, CSV, TXT), построчно отправляет его в языковую модель,
получает шесть полей — **Артикул, Наименование, Единица измерения, Цена,
Кратность упаковки, Примечание** — и показывает их в таблице. Оператор проверяет,
правит и загружает: элементы справочника «Номенклатура» и строки документа
«Заказ поставщику».

Модуль ничего не загружает без подтверждения: любая строка попадает в 1С только
с галочкой «К загрузке».

## 2. Первый запуск: настройки и ключ

1. Открыть обработку **«Умный импорт»** (основная форма — «Умный импорт прайс-листа»).
2. Нажать **«Настройки»** (группа «Файл и настройки»).
3. Заполнить параметры подключения:
   - **Провайдер LLM**, **Модель**, **Адрес сервиса** — из документации провайдера;
   - **Таймаут, с** — обычно 30–60;
   - **Размер пакета** — сколько строк пишется одной транзакцией (по умолчанию 50);
   - **Использовать кэш** — повторные строки берутся из регистра, а не из модели;
   - **Использовать few-shot** и **Максимум примеров** — подмешивание исправлений оператора;
   - **Путь к тест-набору CSV** — только для демо-режима (см. п. 9).
4. Ввести **ключ доступа** в поле «Новый ключ» и нажать «Сохранить».
   В форме видна только маска вида `****1234` — сам ключ не показывается.
5. Если права на изменение настроек нет, форма откроется только для просмотра.

Ключ хранится в константе `КлючLLM`; доступ к ней закрыт ролью «УмныйИмпортНастройки».
Правила и ограничения — в `07-security-checklist.md`.

## 3. Порядок работы с файлом

| Шаг | Действие | Что происходит |
|---|---|---|
| 1 | **Выбрать файл** | Диалог выбора файла. Если поставщик не заполнен, он подставляется из имени файла |
| 2 | Проверить поля «Поставщик», «Настройка импорта», «Максимум строк» | «Максимум строк» = 0 означает «без ограничения» |
| 3 | **Распознать** | Файл читается и уходит в фоновое задание; интерфейс не блокируется, внизу видно «Распознавание выполняется…» |
| 4 | Дождаться заполнения таблицы | В строке состояния: «Готово за N с. Проверьте строки со знаком «!»…» |
| 5 | Проверить строки со знаком **!** | Это «ТребуетВнимания»: модель вернула меньше двух валидных полей либо поле сомнительное |
| 6 | Исправить поля прямо в таблице | Правится любое поле, включая цену и кратность |
| 7 | **Проверить дубли** | Поиск по справочнику «Номенклатура» по артикулу и наименованию; в колонке «Возможный дубль» появляется найденный элемент |
| 8 | **Сохранить исправления** | Правки уходят в регистр «Исправления оператора» и станут примерами для модели. Показывается статистика: сколько пар записано и какие поля правились чаще |
| 9 | Отметить строки галочкой «К загрузке» | **«Отметить все»** отмечает только строки со статусом «ОК». Сомнительные отмечаются вручную, осознанно |
| 10 | Заполнить группу «Загрузка в 1С» | Контрагент, Организация, Склад, Договор, Валюта, флаг «Создавать документ» |
| 11 | **Загрузить в 1С** | Создаются элементы номенклатуры, пишется регистр загруженных строк, при заполненных Контрагенте и Организации создаётся «Заказ поставщику» |

## 4. Колонки таблицы предпросмотра

| Колонка | Смысл |
|---|---|
| Строка файла | Номер строки в исходном файле — по нему легко найти место в прайсе |
| Исходная строка | Текст, который ушёл в модель |
| Артикул, Наименование, Ед. изм., Цена, Кратность, Примечание | Результат распознавания; **редактируются** |
| Уверенность | Оценка модели 0…1; низкая — повод посмотреть строку внимательнее |
| Статус | ОК / ТребуетВнимания / Ошибка / Пропущена / УжеЗагружено |
| Замечания валидации | Что именно не понравилось проверке: «цена указана диапазоном», «единица вне справочника» и т.п. |
| Маркер | Значок статуса: `!` — внимание, `X` — ошибка, `=` — уже загружено, `-` — пропущена |
| К загрузке | Галочка: строка попадёт в 1С |
| Уже загружено | Строка ранее загружалась этим же поставщиком |
| Возможный дубль | Элемент номенклатуры, похожий на строку (после «Проверить дубли») |
| Хеш строки | Служебное: ключ идемпотентности |
| Источник ответа | `Файл` / `Встроенный` / `Нет эталона` — откуда взялся ответ (в демо-режиме) |
| Код HTTP, Токены запроса/ответа, Длительность | Телеметрия вызова: помогает спорить с провайдером и считать деньги |
| Ошибка | Текст ошибки вызова, если строка не распознана |

## 5. Статусы: что делать

| Статус | Когда ставится | Что делать |
|---|---|---|
| **ОК** | Модель вернула валидный JSON, обязательные поля на месте | Проверить выборочно, отметить, загрузить |
| **ТребуетВнимания** | Меньше двух валидных полей, цена не число, единица вне справочника, нет артикула, не распознано наименование | Открыть исходную строку, исправить поля вручную. Строка **не снимается** автоматически — решение за оператором |
| **Ошибка** | Невалидный JSON, таймаут, пустой ответ, недоступность сервиса | Нажать «Распознать» повторно (можно с «Максимум строк»); если повтор не помогает — смотреть колонку «Ошибка» |
| **Пропущена** | Строка отбракована до вызова модели: шапка, «Итого», название поставщика, мусор | Ничего не делать — так и задумано, вызовов модели на мусор не тратим |
| **УжеЗагружено** | Строка с таким же ключом (нормализованные поля + поставщик) уже есть в регистре загруженных | Не загружать повторно: дубль не создастся |

## 6. Загрузка и повторная загрузка

- Загрузка идёт **пакетами** (по умолчанию 50 строк). Каждый пакет — своя транзакция:
  если пакет упал, ранее загруженные пакеты остаются, а в строке состояния появляется
  причина. Остальные строки можно загрузить повторно.
- Номенклатура ищется **по артикулу и по наименованию** до создания. Если артикул
  найден — используется существующий элемент, дубль не создаётся.
- **Повторная загрузка того же файла** дублей не даёт: строки получают статус
  «УжеЗагружено» и в счётчике появляется «пропущено уже загруженных». Это же работает,
  если файл пересохранён под другим именем.
- Документ «Заказ поставщику» создаётся только если заполнены **Контрагент** и
  **Организация**. Иначе загружается только справочник, и об этом прямо сказано в
  сообщении — молчаливого пропуска документа нет.
- Количество в строке заказа = кратность упаковки (если указана), иначе 1;
  сумма = количество × цена.

## 7. Обучение на исправлениях (few-shot)

Каждая правка оператора — учебный пример. После нажатия «Сохранить исправления»
пара «исходная строка → исправленный JSON» попадает в регистр «Исправления оператора»
(только если поля реально изменились). При следующем распознавании 1–3 наиболее
релевантных примера подмешиваются в промпт, поэтому повторяющиеся ошибки постепенно
уходят.

Что важно знать:

- примеры отбираются с приоритетом по поставщику, объём ограничен (лимит 6000 символов),
  чтобы не переполнить контекст модели;
- правка одной и той же строки перезаписывает пару, а не плодит копии;
- статистика правок по полям показывается сразу после сохранения — это основание
  для вывода «модель путает X, надо править промпт».

## 8. Журналы и контроль

| Что | Где | Зачем |
|---|---|---|
| Вызовы модели | регистр «Журнал вызовов LLM» | код ответа, длительность, токены, ответ модели (с замаскированным ключом) |
| Исправления оператора | регистр «Исправления оператора» | что ответила модель, что стало после правки, какие поля изменены |
| Загруженные строки | регистр «Загруженные строки импорта» | ключ идемпотентности: повторная загрузка не создаёт дублей |
| Кэш ответов | регистр «Кэш ответов LLM» | экономия вызовов на повторных строках |

## 9. Демо-режим (без сети и без оплаты)

Если в настройках включён флаг **«Использовать мок LLM»** или **не заполнен адрес
сервиса**, модуль не обращается к провайдеру, а берёт заранее подготовленные ответы:

- из CSV тест-набора по пути «Путь к тест-набору CSV» (по умолчанию — `06-test-set.csv`);
- если файл недоступен — из встроенного мини-набора из пяти строк.

Этот режим нужен для демонстрации и для проверки логики без расходов. Строки, которых
нет в наборе, получают статус «Ошибка» с текстом «для строки не найден эталон» —
это ожидаемое поведение мока, а не сбой модуля.

## 10. Ограничения, о которых нужно знать

1. **PDF не читается.** Формат распознаётся, но текст из него не извлекается: нужна
   внешняя компонента (PDFBox/iTextSharp) или сервис распознавания. Модуль говорит об
   этом явно, а не пропускает файл молча.
2. **Сканы (OCR) не поддерживаются** — это отдельная технология и лицензии.
3. **Файл читается с диска сервера.** При работе через тонкий клиент на другой машине
   файл нужно предварительно поместить во временное хранилище — это доработка.
4. **Ключ хранится в константе без шифрования** (в базовой конфигурации нет БСП).
   Защита — права роли, привилегированный режим и маскирование в журналах.
5. **Неизвестная единица измерения не создаётся**: строка получает «ТребуетВнимания»,
   единица остаётся пустой.
6. **Документ «Заказ поставщику»** создаётся по упрощённой схеме базовой конфигурации:
   шапка заполняется вручную, справочников «Контрагенты»/«Организации» в демо-базе нет —
   реквизиты вводятся строками.
7. **XLSX читается собственным парсером** (без Excel и COM): поддерживаются значения
   ячеек, общие строки и inline-строки, выбор листа. Формулы и стили не вычисляются —
   если в файле только формулы без сохранённых значений, ячейка будет пустой.
