# Сценарий демонстрации «Умного импорта»

Цель показа: за 10–12 минут доказать три вещи — модуль **работает на «грязных»
файлах**, оператор **управляет результатом**, и повторная загрузка **не создаёт дублей**.

## 1. Подготовка (за 30 минут до показа)

| # | Что проверить | Как |
|---|---|---|
| 1 | База развёрнута, расширение `УмныйИмпорт` применено | обработка «Умный импорт» открывается |
| 2 | Настройки импорта заполнены | «Настройки» → провайдер, модель, адрес, таймаут |
| 3 | Режим выбран | **демо без сети:** флаг «Использовать мок LLM» = Истина, «Путь к тест-набору CSV» = `C:\Users\Olgg\УмныйИмпорт\06-test-set.csv` |
| 4 | Ключ задан (если показываем живую модель) | в форме настроек видна маска `****1234` |
| 5 | Демо-файлы на месте | папка `demo` проекта `УмныйИмпорт` |
| 6 | Справочник «Номенклатура» пуст по демо-артикулам | иначе счётчик «создано номенклатуры» будет нулевым |
| 7 | Шапка документа готова | Контрагент и Организация заполнены, иначе документ не создастся |
| 8 | Открыт второй экран/вкладка | регистр «Загруженные строки импорта» и «Исправления оператора» — для показа «внутренностей» |

Файл `04-tehnoplast.xlsx` готовится один раз по рецепту из `demo/README.md`
(Excel/LibreOffice, одна минута). Если его нет — показываем четыре остальных файла,
этого достаточно.

## 3. Ключевые эпизоды (реплики и что должно быть на экране)

### 3.1. «Всё в одной ячейке»

Файл `01-gidromash-all-in-one.txt`:

```
ООО «Гидромаш» — прайс-лист от 01.11.2026
Насос центробежный АЦ-100, арт. 45120, шт., 12 500 руб.
...
```

Ожидаемо: строка «прайс-лист» — **Пропущена** (шапка), пять товарных строк
распознаны. В сводке — сколько строк прочитано, сколько отправлено, сколько пропущено.

Реплика: «Обратите внимание: артикул `45120` вытащен из текста, цена `12 500` стала
числом `12500.00`, единица — `шт`. Ничего не настраивали под этого поставщика».

### 3.2. «Модель ошиблась — оператор исправил»

1. Найти строку со знаком `!` (в моке это `Кратность`/`Ед.` — берём любую строку
   и «портим» её вручную: например, ставим неверную единицу `уп` вместо `шт`).
2. Исправить поле прямо в таблице.
3. Нажать **«Сохранить исправления»** — в строке состояния: сколько пар записано,
   какие поля правились.
4. Открыть регистр «Исправления оператора» — видно `JSONДо`, `JSONПосле`,
   `ПоляИзменены`, дату.
5. Сказать: «Следующее распознавание подмешает 1–3 таких примера в промпт,
   поэтому та же ошибка у этого поставщика уходит».

Честная оговорка для мок-режима: мок возвращает заранее записанные ответы, поэтому
**улучшение ответа** на следующей строке видно только на реальной модели. В мок-режиме
показываем механику: регистр заполнился, статистика посчиталась, примеры попадают в
промпт (`УмныйИмпортПромпты.ПримерыFewShot`, лимит 6000 символов).

### 3.3. «Мусор не стоит денег»

Файл `03-import-trade-dirty.txt`: 7 строк, из них 4 пропущены до вызова модели
(название поставщика, пустая строка, «Итого по разделу:», «Стр. 5»).
Реплика: «Мы не платим за распознавание слова „Итого“».

### 3.4. «Повторная загрузка не создаёт дублей» — главный эпизод

1. Загрузить файл `02-prompodshipnik-table.csv` (или `01`), отметить строки, «Загрузить в 1С».
   В сообщении: «создано номенклатуры: N; использовано существующей: 0».
2. **Не очищая таблицу**, снова нажать «Распознать» на том же файле, затем «Загрузить в 1С».
3. Ожидаемо: строки получают статус **УжеЗагружено** и маркер `=`,
   в сообщении — «пропущено уже загруженных: N», новых элементов номенклатуры нет.
4. Открыть справочник «Номенклатура» и показать, что элементов не прибавилось.
5. Дополнительно: переименовать файл (например, `02-prompodshipnik-table (копия).csv`),
   повторить — результат тот же. Имя файла в ключ не входит.

Реплика: «Ключ идемпотентности — хеш нормализованных полей плюс поставщик.
Поэтому дубли не появляются ни при повторной загрузке, ни при пересохранении файла».

### 3.5. «Загрузка в 1С»

Группа «Загрузка в 1С»: Контрагент, Организация, Склад, Договор, Валюта, флаг
«Создавать документ». После загрузки: «создано номенклатуры: N; использовано
существующей: M; Заказ поставщику: <номер>, строк K».

Если Контрагент/Организация не заполнены — модуль прямо скажет, что документ не
создан, и загрузит только справочник. Это тоже стоит показать как «честное поведение».

## 4. План Б (если что-то пошло не так)

| Риск | Что делаем |
|---|---|
| Нет сети / провайдер недоступен / кончились лимиты | включаем «Использовать мок LLM» и показываем тот же сценарий целиком: логика, статусы, дубли, загрузка — всё работает |
| Модель ответила иначе, чем ожидали | это не сбой: показываем статус «ТребуетВнимания» и правку оператора — сильный аргумент в пользу предпросмотра |
| Не собралась база | показываем **записанное видео** прогона (записать заранее по этому же сценарию) и скриншоты экранов |
| Пустая номенклатура «съехала» | заранее сделать снимок справочника и сравнить количество до/после |
| Не готов XLSX | показываем CSV/TXT, про XLSX говорим: «поддерживается тем же парсером, файл готовится сохранением из Excel» |

Записанное видео — обязательная страховка: оно снимает зависимость демо от сети,
лимитов и состояния стенда.

## 5. Что говорить про ограничения (не прятать)

1. **PDF** — формат распознаётся, текст не извлекается: нужна внешняя компонента или
   сервис распознавания. Сканы (OCR) вне скоупа.
2. **Ключ** хранится в константе без шифрования, доступ закрыт ролью; в конфигурации
   с БСП переезд на безопасное хранилище — правка одного модуля.
3. **Файл читается с диска сервера**; для тонкого клиента на другой машине нужна
   доработка (временное хранилище).
4. **Стоимость**: 200–400 строк в день — это 200–400 вызовов; кэш по хешу строки
   снимает повторные, пакетирование в один запрос сознательно не включено
   (риск падения качества).
5. **Точность**: цифры приёмки — в `04-target-metrics.md`; фактический замер делается
   на реальной модели и реальных прайсах, а не на моке.
